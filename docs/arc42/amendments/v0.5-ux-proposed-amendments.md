# arc42 v0.5: proposed UX amendments (not yet merged)

## Section 1
- FR28 Provide a verdict-first console and pull-request comments in plain language with counts per 1,000 cases, a range, a tolerance line and an evidence chip. Phase 0 to 1.
- FR29 Provide a setup and data-readiness flow, a retirement calendar home, a Review Workbench, an evidence page with versions and a read-only auditor view. Phase 1.
- Stakeholder addition: developers (CI), expert reviewers, auditors as distinct personas with different default views.

## Section 5
- Expand BB13 Console and Reporting: Home, Verdict, Review queue, Evidence, Setup, Alerts and approvals, Rules and definitions, module views, Auditor portal. Add the render library (`omc/render.py`) as the single source of verdict language.
- Add a CI integration component: composite GitHub Action that posts a sticky comment and returns the status code.

## Section 6
- R19 Developer gate: change opened, comment updated, status check, merge.
- R20 Label sprint: batch, blinded comparisons, progress to verdict.
- R21 Auditor verification: shared read-only statement, offline verification, version history.

## Section 8
- 8.23 Verdict language and uncertainty display (ADR-034). 8.24 Reviewer privacy (ADR-035). 8.25 Accessibility (WCAG 2.2 AA). 8.26 States catalogue.

## Section 9
ADR-033 server-rendered UI first; ADR-034 verdict-first language; ADR-035 Review Workbench constraints.

## Section 10
- Q26 Verdict comprehension: at least 85 percent of test participants state the meaning correctly. Q27 Time to first verdict in the console within the 10-business-day target. Q28 Reviewer throughput and agreement reported per batch. Q29 Accessibility: automated and manual checks pass WCAG 2.2 AA on P0 screens.

## Section 11
- R37 Verdict misread as certainty or legal assurance. R38 Review metrics drift into worker monitoring. R39 UI scope creep delays the audit products. R40 Alert fatigue reduces response to retirement notices.
